## 2023-10-27 - [Memoizing Static Filter Transformations in React Renders]
**Learning:** [In Next.js React components with heavily bound state (like a debounced search input), inline array operations—specifically things like `[...new Set(array.map(...))].filter(...).sort()`—can be surprisingly expensive if executed on every render cycle. While small arrays usually don't matter, repeating multi-pass transformations (map, set deduplication, filter, sort) causes unnecessary main thread overhead and GC pressure. I observed this in PracticeUI.tsx where every keystroke fired a state update.]
**Action:** [Always extract complex data transformations on static/slow-moving arrays (like configuration data, category lists, or filters that only change when fetched) into `useMemo` hooks with tight dependency arrays, preventing O(N) operations during high-frequency renders.]
